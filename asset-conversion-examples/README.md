# 素材包转换指南

把一个第三方素材包变成编辑器里可绘制的地形、可放置的物体和可播放的动画。

核心原则只有一条：**按编辑器保存的状态选类型，不按图片长相或排版选类型**。图集的行列、文件编号、颜色都只是存储方式，不携带语义。下文所有规则都是这一条的展开。

参考实现：`asset-conversion-examples/kenney_desert-shooter-pack_1.0/convert/` → `packs/kenney-desert/`，涵盖地形、Wang、物体、动画、UI、字体和声音。遇到本文没写到的情况，先看它是怎么做的。`kenney-pico-8-city` 是测试用包，下文只在需要具体例子时引用它。

**不要假设素材包的结构。** 拿到的包可能只有一张大图，也可能是一堆散图；可能有总览图、示例图、许可证和切片说明，也可能一样都没有。本文的步骤不依赖这些文件：有就用来核对，没有就靠看图和试拼来判断。

---

## 1. 目录与命令

```text
asset-conversion-examples/<原包名>/              原包的完整副本，保持原有目录结构，转换中只读
asset-conversion-examples/<原包名>/convert/      转换脚本、辅助数据（如名称映射）和 README
packs/<pack-id>/               运行时输出，全部由脚本生成，不手改
  pack.meta                    包头：id、name、tileSize、groups、assets 列表
  terrains/ objects/           地形图集、物体与动画条带，每个文件旁有 .meta
  ui/ fonts/ sounds/           按包内实际内容生成，没有就不建
```

在项目根目录依次运行：

```sh
python3 asset-conversion-examples/<原包名>/convert/convert_xxx.py   # 可加 --out 先输出到临时目录
python3 tools/tilemap.py index                       # 更新 packs/index.json
python3 tools/tilemap.py build                     # 重建离线单文件
```

元数据统一通过 `tools/tilemap.py` 的 `write_pack()` 写出，不要自己拼 JSON。它负责 UUID、分组、去重校验和清理旧格式文件。脚本应接受原包路径和 `--out` 两个参数，省略时默认使用上一级目录和 `packs/<pack-id>/`。

运行包只放运行时需要的文件，不放 README、审阅图或许可证副本；许可证留在 `asset-conversion-examples/<原包名>/`。

## 2. 流程

| 步骤 | 做什么 | 产出 |
| --- | --- | --- |
| 1. 入库 | 原包整体复制到 `asset-conversion-examples/<原包名>/`，核对文件数。查找许可信息；找不到就先问来源，不要默认可用 | 只读的原始数据 |
| 2. 测量 | 先看包是散图还是图集。图集要量出单元尺寸、间距和边距：有切片说明（如 `Tilesheet.txt`）就照着读，没有就从透明列、重复周期和散图尺寸反推。目标网格是 32px，像素图用最近邻整数倍放大 | 写进脚本的常量 |
| 3. 读图 | 逐块判断它是完整结构、局部构件、方向变体、外观变体还是动画帧。有总览图或示例图就对照它看组合关系；没有就在脚本里试拼，用试拼结果判断 | 一张"来源 → 用途"表 |
| 4. 定类型 | 按第 3 节为每组图片选数据模型 | 每个输出入口的类型 |
| 5. 列状态 | 写出该类型需要的全部状态，标出原图已覆盖、缺失、重复的部分 | 状态覆盖表 |
| 6. 补片与组装 | 按第 5 节补齐缺失状态，合成跨格结构，切动画条带 | 图集与条带 PNG |
| 7. 写元数据 | 通过 `write_pack()` 生成 meta 和 groups | `packs/<pack-id>/` |
| 8. 验收 | 跑第 8 节清单，生成预览图，在真实编辑器里画一遍 | 测试与预览 |

第 3 步最容易偷懒，也最值钱。连续编号未必是动画，相邻摆放未必同类，颜色相近未必同材质，文件名也可能起错，这些都要看图确认。没有示例图时，试拼出来的预览图就是唯一的依据，所以要保存下来供审阅。

## 3. 选类型

问自己：**编辑器为每个格子存了什么，图片由它怎么决定？**

| 编辑器存的状态 | 类型 | meta 关键字段 | 典型素材 |
| --- | --- | --- | --- |
| 每个世界格"有/无"该地形，显示瓦片看四角 | Dual | （默认，无 `connect`），可加 `height` | 草地、沥青、高台、平顶建筑 |
| 每个格子四条边"接/不接" | Edge | `connect: "edge"`，可加 `height` | 道路、栅栏、围墙 |
| 每个格子的材质标签，按标签兼容选片 | Wang | `connect: "wang"` + `wang` | 多材质过渡的地表、水岸 |
| 一个实体占若干格 | 静态物体 | `footprint` | 房屋、树、车辆的某个朝向 |
| 同一实体随时间变化 | 动画物体 | `frameCount` + `animations` | 行走的人、火堆 |

另外，**手动拼片**（`placement: "tile"`）不是独立的数据模型，而是 Wang 图集的一种交互方式：用户点哪张就铺哪张，不参与自动选片。适用于门窗这类需要用户亲自挑选、自动规则猜不对的构件。

判断时注意以下几点：

- 有边框、有转角并不能说明是哪种类型。Dual、Edge、Wang 的图集都可能长得差不多，区别在于存储的状态不同。
- 一个包通常同时包含多种类型。同一块原图也可能同时进入不同入口，例如既是 Wang 图集里的一块，又被合成进某个物体。但功能相同的入口只保留一个。
- 四种类型都不合适时，宁可做成物体或手动拼片，也不要硬塞进自动地形。

## 4. 各类型约定

### Dual

Dual 只存一件事：**每个世界格有没有这种地形**。同一图层里一个格子只能放一种地形，没有"半格草半格沙"，也没有材质标签。材质之间的过渡靠分图层叠放（例如草地层叠在沙地层上），不靠图集表达。如果素材的核心是多种材质两两过渡，那它应该做成 Wang，不是 Dual。

显示网格相对世界网格偏移半格。每块显示瓦片位于四个世界格的公共角上，按四格占用算 mask：`TL=1 TR=2 BL=4 BR=8`（`shared/grid.js:39`），共 16 种。

图集为 4×4，第 r 行第 c 列放 `sheetLayout[r][c]` 对应的 mask（`shared/config.json`）：

```text
 4 10 13 12
 9 14 15  7
 2  3 11  5
 0  8  6  1
```

- mask 0 全透明，mask 15 是纯内部，不得残留轮廓。编辑器不会自动在下面垫底色。
- 外角（如 mask 1）和内凹角（如 mask 14）是两种不同的边界，不能互相代替。
- mask 6 和 9 是对角占用，图集里各只有一张，画成"相连"还是"分离"由你决定。决定后要写进 README，并在预览里展示出来。

#### 原图不是 Dual 格式时

大多数素材包都不是 Dual 格式，常见的有：以格子为中心的 3×3 九宫格加内凹角、47 块 blob 图集、RPG Maker 式的四分片，或者只有零散的边和角。它们的瓦片以**格子中心**为单位，而 Dual 瓦片以**格子的角**为单位，两者的采样位置差了半格。所以不能挑 16 块重新排列了事，必须重新拼图。

推荐的做法是先拼出一张完整的图，再按半格偏移切开：

1. Dual 图集本身就是一块连续的图。把 `sheetLayout` 反推回世界格，会得到下面这个 5×5 的占用形状（█ 表示有，· 表示无）：

   ```text
   · · █ · ·
   █ · █ █ █
   · █ █ █ ·
   · · · █ ·
   · · █ · ·
   ```

2. 用原图按它自己的规则（九宫格、blob 等）在**普通网格**上画出这个形状，得到一张 5×5 格的连续图。
3. 从第一个格子的中心开始，每隔一格切一刀，切成 4×4 块。每一块正好跨在四个格子的公共角上，按位置排好就是 Dual 图集，mask 顺序自然符合 `sheetLayout`。
4. 用原图拼不出的部分（常见的是内凹角和对角占用），用原图的颜色和线条补画，并在 README 里记下来。

切之前先确认原图在半格处切开不会出问题：轮廓线的宽度、角的朝向、纹理的周期都要能对齐到半格。做不到时只能逐个 mask 手工绘制。


### Edge

一格一张图，按四边连接取 mask：`N=1 E=2 S=4 W=8`。图集按 `edgeSheetLayout` 排列：

```text
 0  2 10  8
 4  6 14 12
 5  7 15 13
 1  3 11  9
```

- 连接以 `links` 的形式按格存储，且**必须两侧互相连接才算接通**。两条并排的路可以互不相连，所以不能用"相邻且同类型"来推测连接。
- 16 种状态是：孤立点、4 种端头、2 种直线、4 种弯道、4 种丁字、1 种十字。同一状态的另一种画法只是变体，不能拿来顶替缺失的状态。
- 所有接口的位置、宽度、颜色和透明边界必须一致。接口以内的部分可以自由发挥。
- 可以用旋转或翻转补出方向，前提是光照、阴影和图案没有方向性。例如原图只画了两个朝向的丁字路口，另外两个可以旋转得到。
- 塔楼、城门这类物体可以通过 `connects: { terrain, sides }` 声明自己哪几条边接受连接，让墙一直延伸到它们身上。

### 高度（Dual 和 Edge 都支持）

Dual 和 Edge 地形都可以抬高，只要在 meta 里加 `height`（格数）和 `extrude` 两个字段：

- `"up"`：涂的格子是底座，顶面往上抬 h 格，适合墙和建筑。
- `"down"`（默认）：顶面留在涂的格子上，墙面往下挂，适合高台和悬崖。

抬高后，图集的每个 mask 区域从 1×1 格变成 **1 格宽、h+1 格高**：顶面在最上面一格，下面是 h 格墙面。16 个区域仍按各自的 layout（`sheetLayout` 或 `edgeSheetLayout`）排成 4×4，所以整张图集是 4 格宽、4×(h+1) 格高（`shared/grid.js` 的 `sheetFrame`）。

- 墙面只需要画朝南的那一面。编辑器从北到南绘制，南边的顶面会自然盖住北边的墙，遮挡关系不需要在图里处理。
- 墙面按左右两半分别判断：上面那格被占、下面那格空着，这一半才画墙，其余地方保持透明。以 Dual 为例，mask 3（TL+TR）整宽都有墙；mask 9（TL+BR）只有左半有墙；mask 13、14、15 下方已被占满，没有墙。拼好后要在预览里检查（参考 `packs/kenney-desert/terrains/mesa.png`）。
- 原图的墙面高度和你设的 `height` 对不上时，要把墙面拉伸或重复到整数格。不能靠在图片上留白来假装有高度。
- Dual 示例：desert 的 `mesa`（1 格）、`mesa_tall`（3 格）。程序绘制示例见 `image-generation-examples/make_dual_plateau.py`，生成 2 格高的 `moss_plateau`；可打开 `image-generation-examples/temp/dual-plateau-demo.html` 查看实际拼接，mask 6、9 的顶面保持分离。
- Edge 示例：城墙、有厚度的围墙。先画出每个 mask 在地面上的形状（中心块加上连接方向的臂），把它向上平移 h 格作为顶面，平移经过的区域就是墙面。这样画出来，南北走向的墙看不到侧面，东西走向的墙露出整段南墙；带 S 臂的墙面会被南边邻格的顶面盖住，画了也没关系。连接口处（瓦片边缘）不要描边，也不要画垛口，否则相邻两格拼接时会出现断缝。 可运行示例见 `image-generation-examples/make_wall.py`；主转换脚本会生成 `terrains/city_wall.png`。用 `maps/城墙验收.tilemap` 或 `image-generation-examples/temp/city-wall-demo.html` 检查转角、丁字口、十字口及遮挡。该示例为程序绘制，并非原包切片。
- Wang 地形不支持高度。

### Wang

每块瓦片用九宫格标注（`annotations`，9 个标签，第 4 位是中心）。四条边由第 1、5、7、3 位推出，顺序为北、东、南、西。用户画的是**中心材质**，编辑器根据周围 8 格的材质选出九宫格最匹配的那块（`shared/wang.js` 的 `wangNeighborhood`）。

meta 的写法（压缩形式由 `tools/tilemap.py` 展开）：

```json
"wang": {
  "labels": ["水面", "草地", "沙滩"],
  "boundary": "水面",
  "columns": 12,
  "tiles": [["0_0", "111111111", 8], ["1_0", "000000000"], null]
}
```

- `tiles` 里每一项依次是来源编号、9 位标签码和可选权重；`null` 表示不可选的分隔格。
- **先定标签语义，再标图**。标签表达的是"能和谁相接"，不等于颜色。两块颜色相同但边界行为不同的图，需要用不同的标签。
- `boundary` 表示空格和其他地形邻居的取值。地图外不做约束。只有在确实存在"边界材质作中心"的过渡图时，才开启 `boundaryTransitions`。
- 标注完全相同的瓦片之间才会按 `weight` 随机挑选。权重只影响外观，不能改变连接含义。
- 如果某些邻域组合没有图可用，要明确选择一种处理：补片、限制可画的材质，或者改成手动拼片。不能让它静默选到一块无关的图。

### 物体与动画

- **锚点是固定的**：图像的底边对齐占地的底边，水平方向居中，绘制顺序按占地底边排序（`shared/grid.js` 的 `objectRect` 和 `objectDepth`）。meta 里没有锚点字段，所以要靠**出图**来对齐。高出占地的部分（屋顶、树冠）直接向上延伸。
- `footprint` 只写真正挡路的格子。高大物体通常只占底部一两行，高出的部分不算占地。
- 跨多个格子的结构（房屋、办公楼）要先在脚本里拼成一张完整的图，再作为一个物体输出。不能把每个切片都当作独立物体暴露出来。
- 动画是一条横向条带，由 `frameCount` 张等宽帧组成。`animations: [{ name, label, frames, fps }]` 的第一项是默认动作。帧序可以复用，例如行走动画写成 `[0,1,0,2]`。
- 各帧的画布尺寸和对齐必须一致。如果原图裁掉了透明边，要在拼条带时把偏移还原。
- 朝向和配色是**不同的物体**，不能把它们排成动画轮流播放。例如车辆的四个朝向应该是四个物体。真正的帧动画参考 desert 的 `door_blue_animated`、`chest_red_animated`。
- 预览背景、棋盘格以及示例图里的阴影不是素材，不能混进输出的 alpha 通道。

## 5. 缺片、补片与去重

先有第 2 节第 5 步的状态覆盖表，再动手补片。补片手段按优先级排列：

1. 原图里已有、语义也相同的区域。
2. 对原图做旋转或翻转（需要核对光照和图案）。
3. 按目标边界切分后重新组合（四分片）。
4. 用原图调色板重绘，例如原图缺内凹角时，用原图的边框颜色画出来。

每一块补出来的图都要在 README 里写明来源和补法。

去重按**功能**判断，而不是按文件名或像素：

- 功能完全相同的入口合并成一个。例如 Dual 建筑已经能自动生成屋顶和墙面，原来的手动屋顶拼片就应删除。
- 像素相同但语义不同的资源要分别保留。例如同一块图既在 Wang 图集里，又作为物体的一部分。
- 换掉一个旧入口时，要直接删除旧产物，并在 README 写明"不保留兼容入口"和原因。是否给旧地图提供迁移，单独决定，不要靠长期保留重复入口来回避。

## 6. 可重复性与资源身份

- 切片、放大、补片、合成、分类、动画和元数据全部由脚本完成，不允许任何手工改 PNG 或 meta 的步骤。路径都相对 `ROOT`，不写死绝对路径。
- **UUID 是地图引用资源的唯一依据**。`write_pack()` 会优先沿用同路径已有的 UUID，没有时才用 `uuid5('tilemap:<pack-id>/<meta 路径>')` 生成。因此，**改输出文件名等于换身份**，已保存的地图会丢失引用。真要改名，必须手动带上旧 UUID。
- 记录来源和输出的对应关系，包括哪些原图被合并、被替代、被补片或被弃用，以及原因。规模小的写进 README 即可；数量大时可以生成映射文件，例如 `packs/kenney-pico-8-city/source-map.json`。记录只说明这张原图处理过，不说明它被逐像素用上了，所以覆盖率不能代替第 3 步的人工判断。
- 重复运行脚本，结果必须一致：已废弃的本包产物要被清理，原始数据和其他包不受影响。可以先用 `--out` 输出到临时目录再比对。

## 7. 命名与分类

- **资源名**：文件名用 snake_case 英文，描述"是什么"加上必要的差异，例如 `tree_purple`、`bush_teal`。`label` 是给用户看的中文名，名称多时可以放进映射文件（如 desert 的 `convert/object-labels.json`）。
- **分类**（`pack.meta` 的 `groups`）按用户找东西的方式来分，例如 desert 分成"场景""物品""角色"，不照搬原包的目录或图集顺序。分类名要短，不加前缀和分隔符，也不重复资源名里已有的信息。
- 手动拼片图集要保留原图的组合关系，同组构件连续摆放，中间用 `null` 分隔格隔开。
- 图集的**展示顺序**和**逻辑映射**分开维护：Dual 和 Edge 的位置由 layout 决定，Wang 由标注决定，所以调整展示顺序不会改变选片结果。

## 8. 验收清单

每一条都要在真实的编辑器里看过，或者有测试覆盖。只看导出的整张图不算数。

- [ ] **类型**：每个入口的类型都能说出理由，静态变体没有被做成动画，完整结构没有被拆散。
- [ ] **状态**：Dual 和 Edge 的 16 个 mask 都有图，Wang 的每种材质组合要么能选到图，要么有明确的处理办法。
- [ ] **接缝**：画一块包含矩形、内凹角、孔洞、窄条、孤立格和对角占用的区域，检查所有接缝连续、透明边干净。
- [ ] **几何**：物体底边对齐占地，高物体的遮挡关系正确，抬高地形的墙面只出现在暴露的那一侧。
- [ ] **动画**：完整播放一轮，没有跳动、缺帧、闪烁，循环衔接处也自然。
- [ ] **操作**：绘制、覆盖、擦除、撤销、重做，保存后重新打开，结果保持一致。
